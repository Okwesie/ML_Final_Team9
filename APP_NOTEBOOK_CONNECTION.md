# How the Streamlit App Connects to the Notebook

## Overview

The Streamlit app (`app.py`) is a **deployment interface** that uses the models and data generated by running the Jupyter notebook (`Team_9_Final_Project.ipynb`). They work together as follows:

```
Notebook (Training) → Models/Data Files → Streamlit App (Deployment)
```

## Connection Flow

### Step 1: Notebook Generates Outputs

When you run the notebook, it creates:

```
models/
├── non_personalized_model.pkl          # IMDB-weighted score model
└── content_based_best_model.pkl        # Random Forest model

outputs/
├── hidden_gems.csv                      # High-quality, low-visibility movies
├── executive_summary.json               # Key metrics and insights
└── model_comparison.csv                 # Model performance metrics
```

### Step 2: App Loads These Files

The Streamlit app loads these files to provide interactive features:

```python
# In app.py
models['non_personalized'] = joblib.load('models/non_personalized_model.pkl')
models['content_based'] = joblib.load('models/content_based_best_model.pkl')
hidden_gems = pd.read_csv('outputs/hidden_gems.csv')
```

## Detailed Connections

### 1. **Recommendation Models**

**Notebook (Part 3):**
- Trains `NonPersonalizedRecommender` class
- Trains `ContentBasedRecommender` class (Random Forest)
- Saves models using `joblib.dump()`

**App:**
- Loads models using `joblib.load()`
- Uses `recommend()` method for top-N recommendations
- Uses `find_similar_movies()` for content-based discovery

**Connection Point:**
```python
# Notebook saves:
joblib.dump(non_pers_recommender, 'models/non_personalized_model.pkl')

# App loads:
non_pers_model = joblib.load('models/non_personalized_model.pkl')
recommendations = non_pers_model.recommend(n=10)
```

### 2. **Hidden Gems Data**

**Notebook (Part 4):**
- Calculates hidden gems (high-rated, low-visibility movies)
- Saves to CSV: `hidden_gems.to_csv('outputs/hidden_gems.csv')`

**App:**
- Loads CSV: `pd.read_csv('outputs/hidden_gems.csv')`
- Displays in "Business Insights" → "Hidden Gems" tab

**Connection Point:**
```python
# Notebook:
hidden_gems.to_csv('outputs/hidden_gems.csv', index=False)

# App:
hidden_gems = pd.read_csv('outputs/hidden_gems.csv')
st.dataframe(hidden_gems)
```

### 3. **Executive Summary**

**Notebook (Part 5):**
- Generates key metrics dictionary
- Saves to JSON: `json.dump(executive_summary, f)`

**App:**
- Loads JSON: `json.load(open('outputs/executive_summary.json'))`
- Displays metrics in "Business Insights" → "Overview" tab

**Connection Point:**
```python
# Notebook:
executive_summary = {
    'total_ratings': f"{total_ratings:,}",
    'unique_users': f"{unique_users:,}",
    # ... more metrics
}
json.dump(executive_summary, f)

# App:
summary = json.load(open('outputs/executive_summary.json'))
st.metric("Total Ratings", summary['total_ratings'])
```

### 4. **Model Comparison**

**Notebook (Part 3):**
- Compares all models (Random Forest, Ridge, KNN)
- Saves comparison: `comparison_df.to_csv('outputs/model_comparison.csv')`

**App:**
- Loads comparison: `pd.read_csv('outputs/model_comparison.csv')`
- Displays in "Model Performance" page

**Connection Point:**
```python
# Notebook:
comparison_df.to_csv('outputs/model_comparison.csv', index=False)

# App:
comparison_df = pd.read_csv('outputs/model_comparison.csv')
st.dataframe(comparison_df)
```

### 5. **Movies Data**

**Notebook:**
- Loads and processes `movies.csv`
- Creates features (genres_list, release_year, etc.)

**App:**
- Loads `movies.csv` for movie search functionality
- Uses for displaying movie titles and genres

**Connection Point:**
```python
# Both use:
movies_df = pd.read_csv('movies.csv')  # or 'data/movies.csv'
```

## Usage Workflow

### First Time Setup:

1. **Run the Notebook:**
   ```bash
   # Open Team_9_Final_Project.ipynb
   # Run all cells
   # This creates models/ and outputs/ directories
   ```

2. **Start the App:**
   ```bash
   streamlit run app.py
   ```

3. **In the App:**
   - Click "🔄 Load Models" in sidebar
   - Click "📊 Load Data" in sidebar
   - Navigate to different pages

### Subsequent Uses:

- If models/data already exist, just start the app:
  ```bash
  streamlit run app.py
  ```
- Models are cached, so loading is fast

## Troubleshooting

### "Models not found" Error:

**Solution:**
1. Make sure you ran the notebook completely
2. Check that `models/` directory exists
3. Verify files: `ls models/`

### "Data not found" Error:

**Solution:**
1. Run the notebook to generate outputs
2. Check that `outputs/` directory exists
3. Verify files: `ls outputs/`

### Models Load But Don't Work:

**Solution:**
1. Make sure you used the same data in notebook and app
2. Check model compatibility (same sklearn version)
3. Verify the model classes match

## Best Practices

1. **Always run notebook first** before using the app
2. **Keep data consistent** - use same dataset versions
3. **Version control** - track which notebook version created which models
4. **Test after changes** - if you modify notebook, retrain models
5. **Document versions** - note sklearn/pandas versions for reproducibility

## Summary

The notebook is the **brain** (trains models, analyzes data), and the app is the **face** (interactive interface). They're connected through:

- **Models**: Saved `.pkl` files
- **Data**: CSV and JSON outputs
- **Same Logic**: App uses same classes/methods from notebook

This separation allows:
- Notebook: Deep analysis, experimentation, training
- App: Clean interface, easy sharing, stakeholder demos

---

**Remember:** The app is a **consumer** of the notebook's outputs. Always run the notebook first!
